# 迭代 6 复盘：批量重复运行与评测标定

## 一、迭代目标

解决当前平台“只能跑单次运行、无法量化随机性与稳定性”的问题：
1. **支持单场景重复运行（Repeat）**与**多场景批量运行（Batch）**；
2. **量化方差与科学性标定（Variance & Judge Calibration）**：耗时分布、工具调用频次/方差、交互轮次、Judge 稳定性；
3. **统一批次产物与 API 控制面**：`reports/batches/<batch_id>/`、`/api/batches` 与 SSE 实时事件。

## 三、最终复盘与总结

### 1. 核心收获与解决的问题
- **从“单次随机运行”迈向“统计学可靠评测”**：引入 `repeat_count` 与 `BatchRunner`，使 GeoSkillBench 能够衡量 Agent 在相同任务下的稳定度（Pass Rate、轨迹熵、耗时分布），消除了单次随机波动对评测结论的干扰。
- **多维度过程方差量化**：不仅统计最终成败，更通过工具调用频次分布、轨迹离散度（Shannon Entropy）、对话轮次分布深入分析 Agent 的行为漂移。
- **完备的产物与控制面闭环**：
  - 文件系统：`reports/batches/<batch_id>/summary.json` 与 `summary.md` 独立留痕；
  - 数据库：`batches` 表持久化聚合结果并与子 run 建立关联；
  - API & SSE：支持前后端全异步批量下发与实时事件广播。

### 2. 遗留事项与后续方向（迭代 7+）
- 当前批次调度默认采用串行调度（`concurrency=1`），后续可根据外部 GIS 服务承载能力平滑引入并发池；
- 下一步（迭代 7）可在此统计基座上，深入拓展空间关系规则（`spatial_relation`）、几何拓扑有效性等 GIS 领域特色确定性断言。
