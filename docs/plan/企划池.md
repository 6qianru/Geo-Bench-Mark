## 1. 批量重复运行与聚合评分

- **来源**：迭代 5（真机标定批次）实验设计要求"同一场景连跑 N=3~10 次"；也是方差缓解阶梯第 4 层的产品化。
- **内容**：
  - API：run 触发支持 `repeat: N`（或新增批量端点），N 次独立 run 共享一个批次号；
  - 聚合视图：通过率 / judge 均分与极差 / 断言翻转计数，按批次查询（`GET /api/runs/aggregates` 设想来自迭代 1 计划）；
  - 报告标注聚合口径（多数投票 / 均分），DB 已按 scenario_id 存历史行，聚合是查询层的事。
- **价值**：迭代 5 的跑批摩擦直接消除；若方差量化结论是"不可接受"，这就是官方评分口径。
- **改动面**：runner（循环触发）/ api / db（聚合查询）/ 前端入口 / markdown 报告模板。
- **提拔时机**：迭代 5 启动前顺手实现最划算——标定批次直接在它上面跑。**本条目可能最先被提走。**

## 2. 报告地图可视化

- **来源**：result_* 结果内容断言已有数值比对（overlap_ratio / hausdorff 等），但没有"看一眼"的途径。
- **内容**：报告页嵌入 Leaflet 地图，结果 GeoJSON 与 `data.reference` 参考数据叠加渲染，差异区域高亮；数据源用 `reports/outputs/<run_id>/` 下已落盘的结果文件，reports API 需补对应内容端点。
- **价值**：GIS 平台的直观证据；人工核对 judge/断言结论时有据可看。
- **改动面**：前端为主（Leaflet 本地打包，注意离线部署）；后端仅补一个结果文件读取端点。
- **注意**：大文件渲染上限（要素数阈值 + 缩略/抽样），避免报告页卡死。

## 3. spatial_relation 断言

- **来源**：design/00 §10 规划期设计（当前未实现）；result_* 五指标只回答"像不像参考"，回答不了"空间关系对不对"。
- **内容**：对结果数据集做硬校验——`intersects`（相交指定图层）/ `contains`（包含指定点集）/ `distance_max`（与目标图层面距离上限）/ `disjoint`（不得触碰）。参数形如 `{ type: spatial_relation, target: buffer_result, relation: contains, other: schools }`，`other` 从 fixtures 解析。
- **价值**：不需要 reference 文件即可表达"缓冲区必须包含所有学校"这类领域规则；是 GIS 平台区别于通用 agent benchmark 的差异点。
- **改动面**：assertion_engine 新 handler + result_comparator 复用几何加载/UTM 对齐；guide §10、design/00 §10 补文档。
- **依赖**：shapely（result_comparator 已在用，无新依赖）。

## 4. forbidden_behavior 规则断言

- **来源**：design/00 §10 规划期设计；现状 `should_not` 只喂 LLM judge 作软参考，无确定性失败路径。
- **内容**：对对话/工具轨迹做规则匹配（关键词/正则/工具名黑名单），命中即断言 fail——把"禁止行为"从扣分项升级为硬性失败项。
- **价值**：需要"确定性红线"的场景（如不得绕过授权直接调工具）有用。
- **保留意见**：与 judge rubric 功能重叠；只有当软扣分不够、必须硬卡时才值得做。**优先级最低的断言类条目。**

## 5. Judge 结构化输出增强（response_format）

- **来源**：迭代 2 计划 §3 留的口子——当前 prompt 要求纯 JSON + 宽松解析 + 重试一次，不依赖 `response_format`（模型能力当时未确认）。
- **内容**：LLM 可用时加 `response_format={"type":"json_object"}`（OpenAI-compatible 通用扩展），降低 JSON 解析失败率与重试开销。
- **提拔时机**：迭代 5 judge 质量评估显示 `judge_mode=llm` 成功率明显受解析失败拖累时再做，拿数据说话。

## 6. 反问协议结构化

- **来源**：design/02 §12.1"后续可以改为结构化输出"。
- **内容**：以工具调用或 JSON 标记替代 `[NEED_INTERACTION]` / `[FINAL]` 文本前缀，消除措辞漂移导致的误判。
- **保留意见**：文本协议的最大优点是任意 OpenAI-compatible 端点、任意外部 agent 都能跑；结构化要求被测方配合，反而抬高接入门槛。除非误判率实测可观，否则不动。

## 7. nanobot 真实运行时接入

- **来源**：design/02 全文推演；当前 `nanobot` executor 为兼容模式占位（保留 executor/session/task API，结果带兼容注记）。
- **内容**：接入真实 nanobot Python runtime：注入 skill prompt / 注册 MCP tools / 回传 tool_calls（见 design/02 §11 实现思路与 §7 前提清单）。
- **提拔时机**：出现真实的 nanobot 评测需求。无需求驱动前保持占位。

## 8. 云端数据面打通

- **来源**：迭代 4 复盘 §7。
- **内容**：fixture 语义能否映射云端数据集接口——本地 fixture 是"文件注册"，云端是"数据集 ID 引用"；需要评估注册/引用协议、鉴权、以及 result_* 比对所需的"拉取结果到本地"路径是否成立。
- **前置**：云端账号与接口权限就位后立项评估。

## 9. 前端表单覆盖复杂配置块

- **来源**：guide §13 边界——断言（result_* 已支持逐条添加）、expected_behavior、自定义 flow、mcp servers 细节等表单未完整暴露，靠手改 yml。
- **内容**：按使用频率逐步补表单项；管理入口（YAML 原文编辑）已兜底，所以这是易用性打磨而非缺口。
- **提拔时机**：非开发者用户开始高频写场景时。
